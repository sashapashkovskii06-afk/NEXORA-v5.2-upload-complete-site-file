# NEXORA v5.2 — Luxury Chrome

Полный стартовый комплект NEXORA: сохранён существующий интерфейс, добавлен серверный backend, отдельные аккаунты, email-подтверждение, публичные профили, статистика просмотров/кликов, публикация тем, загрузка видео/музыки, промокоды Premium и закрытая панель владельца.

## Что находится в комплекте

- `app.py` — Flask backend и API.
- `templates/index.html` — существующий интерфейс NEXORA.
- `templates/public_profile.html` — публичная страница `/u/<ник>`.
- `templates/admin.html` — панель владельца `/admin`.
- `requirements.txt`, `Procfile`, `runtime.txt` — запуск на Python-хостинге.
- `tests/test_app.py` — базовые smoke-тесты для проверки запуска и API.
- `.env.example` — список настроек, которые нужно заполнить на хостинге.

## Важно перед публикацией

**Не загружай реальные пароли, SMTP-пароль, секретный ключ или адрес базы с паролем в GitHub.** Настройки добавляются в разделе Environment Variables / Secrets на хостинге.

Для постоянной работы на хостинге настрой:

1. `SECRET_KEY` — длинная случайная строка.
2. `DATABASE_URL` — PostgreSQL от хостинга/провайдера базы данных. Если не указать, приложение использует локальный SQLite; на некоторых бесплатных хостингах его файл может исчезнуть после перезапуска или пересборки.
3. `OWNER_EMAIL` — email владельца. Именно этот email получает права Creator Admin при регистрации.
4. SMTP-параметры (`SMTP_HOST`, `SMTP_PORT`, `SMTP_USER`, `SMTP_PASSWORD`, `SMTP_FROM`) — без рабочего SMTP коды подтверждения email не отправятся, и регистрация не завершится.
5. `COOKIE_SECURE=true` при HTTPS.

После первого успешного деплоя проверь адрес `/health`: должен вернуться JSON со статусом `ok` и базой `connected`. Перед публикацией можно выполнить `python -m unittest discover -s tests` после установки зависимостей.

## Загрузка на GitHub с телефона

1. Распакуй ZIP на устройстве.
2. Открой репозиторий GitHub и загрузи **все файлы и папки** из `NEXORA_READY` в корень репозитория, а не саму папку как вложенную папку.
3. Сделай Commit changes.
4. На хостинге выбери этот репозиторий и Python/Gunicorn-команду из `Procfile`.
5. Добавь переменные окружения из `.env.example` и подключи PostgreSQL.
6. После деплоя открой `/health`, затем зарегистрируй владельца с email, указанным в `OWNER_EMAIL`.

Если в репозитории уже есть другие файлы приложения, перед заменой сохрани резервную копию. Не удаляй конфигурацию базы данных, если текущий хостинг уже использует собственную схему подключения.

## Проверка перед запуском

- Python 3.12 рекомендуется для совместимости с указанным `runtime.txt`.
- Не публикуй файл `.env` и не вставляй реальные секреты в исходники.
- Для продакшена обязательны стабильный `SECRET_KEY`, постоянная PostgreSQL-база и работающий SMTP-провайдер.
- Проверь регистрацию, подтверждение email, выход/повторный вход и публичную ссылку после деплоя.

## Функции и ограничения

- Пароли хранятся в виде стойких хешей; сессии используют подписанные cookies.
- Данные профиля хранятся отдельно по ID пользователя; публичная ссылка имеет вид `/u/username`.
- Сервер сам проверяет право на Verified, Creator и Premium-значки; клиент не может назначить себе эти права одним изменением HTML.
- Владелец может выдавать/снимать Verified, назначать Premium и создавать промокоды в `/admin`.
- Покупки банковской картой/Stripe **не подключены**. Premium можно выдать администратором или промокодом; реальные платежи требуют отдельной платёжной интеграции и её ключей.
- Видео и аудио сохраняются в `static/uploads`. Для долговременного хранения на хостинге нужен постоянный диск либо объектное хранилище; если бесплатный хостинг очищает файловую систему при деплое, пользовательские медиа нужно вынести в отдельное хранилище.
